# Coding agent 施工指南

## 1. 产品目标

构建一个可运行的模型前端作品展示与对比页面。观众选择任务后，能直观看到不同模型的设计方案、最终页面、实际交互表现，以及生成代码。每个模型同题默认运行五次，五次均保留，便于观察质量与稳定性。

这个输入包就是题库。保持 01–20 的 case id、题目和来源，读取 `manifest.json`，不要再用你自己的记忆重建题库。默认使用本包 full prompt；short 与 original 是不同实验组，明确标注。

## 2. 页面与浏览体验

- 顶部提供任务、模型、运行次数和展示模式的选择。任务按 visual、simulation、logic、interactive、product 分类，可按名称搜索。
- 任务详情显示题目、完整 prompt、输入素材、原始来源和本包改写说明。JSON、SVG 输入可展开查看，并能下载对应文件。
- 对比区以模型为行、run 1–5 为列。卡片显示模型名、运行编号、状态及缩略图；点击打开详细结果。模型数量多时保持清楚的滚动或分页。
- 支持选择 2–4 个结果放大并排比较。先显示静态图或录像缩略图，用户明确进入交互模式后再加载 live preview，避免同时运行大量 WebGL 场景。
- 详细结果包含四个视图：公开设计方案、运行效果、操作后的状态、代码。代码按 HTML/CSS/JS 分析展示或至少提供原文件，支持复制、搜索与下载。
- 设计方案读取 plan.json，而不是猜测模型当时的想法。代码高亮不替代完整原文件。关键函数若自动提取，要保留它的来源位置。
- 动画可同步重播，同组截图使用同一视口。可在 desktop 1280×800 与 mobile 390×844 切换，记录素材的实际尺寸。
- 当某次失败、未开始或无截图时，明确显示状态。不能从五次中只展示最好一次，也不能用题目输入 SVG 当作模型生成截图。

## 3. 数据导入与模型生成分开实现

首个可交付版本应能导入真实生成文件并完成展示，不需要模型 API 就能检查页面结构。
支持导入一个结果 ZIP 或读取 results/index.json；按 OUTPUT_DATA_CONTRACT.md 对齐 case_id、model_id、run_number。
只允许导入同一 schema 的结果，发现缺少 artifact 或非法 JSON 时给出清楚错误。

在没有模型结果时显示题目与输入、未生成状态，可使用清楚标为 UI fixture 的开发样例验证组件；这些样例不得加入模型榜单或宣称来自真实模型。
只有用户授权并提供模型访问配置后，才接入批量生成。密钥放在服务端或本地受控配置中，不放进浏览器 bundle。

## 4. 五次独立生成的工作流

1. 每个模型每题创建 run-1 到 run-5 五个独立目录。每次用新会话，不带入其他 run 的回答。
2. 用 scripts/prepare_case.py 准备该题，读取 request.json 中的 system/user 和 assets。不要给模型看 SOURCE.md 中的成品画廊链接、观察清单或其他模型答案；如果需要纯 text-to-code 比较，则不允许浏览来源网站。
3. 保存发出的完整 system/user、模型完整 id、生成参数、工具权限和预算。
4. 收集 plan.json、artifact.html 和实际执行日志。agent 模式下保留调试次数，单次输出模式中不悄悄修复。
5. 本地 HTTP 环境中打开 artifact.html，先记录是否加载、是否出现可见内容及 console error，再记录视觉效果。为每次运行截图；动态题录制同样八秒。
6. 按 case.json 的 interaction_actions 执行同样的语义操作并记录后续截图/录像。它们是建议，不是现成自动化脚本；实际控件选择器应在生成后解析或人工确认。
7. 成功、失败、截断和修复后的结果都入库。把生成失败与渲染失败分开记录。

## 5. 运行与资源

默认作品是单 artifact.html，引用 ./assets 和 ./vendor。默认无在线资产，Three.js 0.180.0 与 OrbitControls 已附。
展示系统预览时要为每个 run 保持相对文件路径，不能只拿 HTML 字符串丢进 srcdoc 后让素材路径失效。
生成作品的 HTML 是可执行代码：将预览放在隔离 iframe/预览域中；不要在展示应用主文档执行，也不要把主站账户、密钥或应用存储交给作品。需要 localStorage 的第 15 题应使用与主站隔离的专属预览 origin。
模拟终端只支持给定模拟命令。第 20 题地图是示意地图，输入完全虚构，没有后端和实时 OSINT API。
React 空项目仅用于单设 JSX 赛道，默认 20 题不需要 npm 安装。不要把一个模型的 React 版本与其他模型的默认 HTML 版本混成同一组。

## 6. 首批与验收

首批重点检查 01、02、03、06、14、15、18、19；其余题目仍应能从同一数据结构读取。
验收时检查：
- 20 个 case 全部能浏览，prompt 和素材可以打开。
- 每题每模型显示五个运行槽位，顺序固定，失败不隐藏。
- 能导入一个含 plan.json、artifact.html、截图的真实 run，并正常加载相对素材。
- 能并排看两个结果、查看方案、切换代码和放大画面。
- 01 的 SVG、03 的 Three.js、19 的固定商品素材、15 的独立存储可以正确预览。
- 未生成/失败/修复状态、来源与改写身份都表达清楚。
- 没有调用模型时不显示虚构时间、token、评分或模型成品。

请在施工完成后交付可运行项目、启动命令、数据导入方法和已验证事项。若缺少模型访问方式，完成展示与导入部分，并明确这一限制；不要把 API 凭据作为搭建展示页的前置阻塞。
