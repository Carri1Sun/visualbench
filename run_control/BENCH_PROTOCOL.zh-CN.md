# VisualBench 本轮执行协议

本项目直接展示模型产物、三次重复运行、公开方案、源码与执行轨迹。页面不设置审美分数、排行榜或 rubric。

## 固定实验条件

- 题库：`frontend-showcase-inputs-v1` 20 题，`video-bench-inputs-v1` 20 题；原始目录保持不变。
- 模型：DeepSeek Flash、GLM 5.3、GLM 5.3 Flash、GPT 6.1 Sol、GPT 6 Astra；真实 Provider 和模型 ID 见 `bench/config.json`。
- 每题每模型 3 个独立目录和 Pi 会话，共 600 次。保留所有完成、失败、超时与中断记录。
- 失败同样占一次运行，不通过追加模型调用凑齐成功样本。较弱成品原样展示，人工失败标记单独留存。
- 提示：中文完整提示。前端作品中的可见文案遵循题包要求使用英语。`short` 和视频四档指导强度未纳入本轮。
- 思考：初始五个模型均请求 `max`。2026-10-03 按用户要求，Astra 与 Sol 在切换时尚未启动的槽位统一改为 `high`；已结束和正在运行的 `max` 样本保留原设置，不追加重跑。本轮包含两档思考设置，每次运行单独保存 requested/effective 和原始启动命令；切换边界、具体槽位与进程交接见 `data/execution-changes.json`，不将已有 max 结果标成 high。
- Harness：Pi 0.99.2，仅启用 read、bash、edit、write。关闭自动发现的技能、扩展、上下文文件、提示模板，以冻结共同工具条件。
- 每次 agent 会话预算 45 分钟，独立外部渲染预算 30 分钟；统一允许会话内调试。未设置额外 token 或费用上限。未知 temperature/seed 保留 null。
- 并发：初始每模型 1 个生成 worker；2026-10-03 按用户要求提高至每模型 3 个，总共 15 个。媒体捕获保持单独串行队列，依赖预热时间不计入生成耗时。切换时原 Pi 进程继续运行，交接及生效时间记录在 `data/execution-changes.json`；交接样本无法获取的原进程退出码明确记为未知，不重启模型会话。
- GLM 5.3 在本地 Pi 注册表中标为仅文本输入。保留这一模型能力差异，未引入替代视觉模型。

## 可复核性

每次运行保存完整提示、输入哈希、原始模型会话、工具事件、公开设计方案、源码哈希、执行状态、真实 usage、构建/渲染观测和媒体。Pi usage 中的费用可能来自模型目录估算，不能作为实际账单。

公开 trajectory 包含 Pi 原生 JSONL 和 `pi --export` 生成的本地可打开 HTML，逐一绑定题目、模型、run 编号。原始会话和原始工具日志在 `private/` 中保留；HTTP 服务只公开专门导出的 trajectory 文件。轨迹可能包含模型的中间生成内容，公开方案另有独立入口。

模型从干净题目项目开始，只获准处理当前目录、固定素材和本地依赖。源码不经策展方美化或代写。模型可在同一次会话中修复自己的代码；额外执行和续跑均保留轨迹。本地进程按当前用户权限运行，目录与提示约束不提供操作系统级沙箱。

技术验收与视觉判断分别呈现。页面的成功状态表示技术产物可展示，无法据此推断任务语义完整、交互全部正确或审美优秀。参考素材明确作为输入呈现。

## 捕获

前端默认 1280×800，加载两秒后截图，保留八秒屏幕录制；16–20 产品题增加 390×844 手机截图。专用捕获 origin 与用户预览 origin 分离，捕获时清理该专用 origin 的存储，避免跨运行继承状态。可交互预览按需加载，作品和主展示页使用不同 origin。

视频保留题目原始尺寸、30 FPS 与完整时长；收集 H.264 预览、海报和六张等距关键帧。03/13 另检查带 alpha 的 ProRes 母版。外部补渲染保持模型源码不变，构建或渲染失败也保留已生成文件。关键帧和媒体参数不能替代完整任务人工检查。

## 范围

本轮的输入方式标签描述已有题目；不同主题不能构成指导强度的因果对照。手机截图针对产品网页的响应式表现，目前没有独立移动端应用题组。未来扩展需另冻结实验条件并分组展示。
